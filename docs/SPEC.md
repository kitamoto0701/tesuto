# 要件・画面・運用の前提

## 確定事項
- クラウド方式、最大10人、個別ログイン。GitHub `kitamoto0701/tesuto` で開発継続。
- 先行パッケージの台帳機能を引き継ぎ、管理者・工事担当・経理担当を用意。
- パスワード・機密情報を公開ソースに含めない。

## 今回の仮定
- 1社専用・社内共有。複数会社分離や案件ごとの閲覧制限は対象外。
- 10人は「有効なアカウント数」、管理者を含む。無効化済みアカウントは数えない。同時接続を10本に制限する意味ではない。
- 金額は全て日本円・税抜。小数2桁で保持、見積は数量×単価を四捨五入。税計算・会計仕訳は未実装。
- 工事担当へ契約額や会計台帳を公開しない。契約額の登録・変更は管理者が行う。
- 台帳は個別入力。見積承認から発注・請求への自動連携、二重計上検出は未実装。
- 誤登録は編集で訂正。案件状況欄に「中止」等を記録可能。削除・取消伝票・承認ワークフローは未実装。

## 画面構成
| 画面 | 内容 |
|---|---|
| ログイン | ユーザー名・パスワード、5回失敗で15分制限 |
| ダッシュボード | 案件数・期限超過工程数・利用者数・進捗、会計権限者には工事別収支 |
| 工事案件 | 番号・名称・住所・発注者・担当者・着竣工日・契約額・状況・進捗 |
| 協力業者 | 会社・担当者・連絡先・業種 |
| 見積 / 実行予算 | 数量×単価の自動計算、工種別予算 |
| 発注 / 原価 | 発注先・内容・金額、原価計上 |
| 請求・入金 | 請求額・累計入金額・入金予定日（入金額≤請求額） |
| 工程 | 案件・作業・担当者・開始終了・進捗0～100% |
| 日報 / 安全 | 日付・作業・人数・安全事項等 |
| 図面・写真台帳 | 保存先文字列のみ。URLは自動取得・リンク化しない |
| 担当者・ユーザー | 管理者による追加・無効化・再有効化・パスワード再設定 |
| パスワード変更 | 本人による変更 |
| 操作履歴 | ログイン、登録、編集、CSV出力、ユーザー操作の直近200件 |

各台帳は新規登録・編集・検索・50件ごとのページ送り・UTF-8 BOM付きCSV出力に対応。工程は一覧形式で、ガントチャートや自動工程計算は未実装。

## 権限表
| 機能 | 管理者 | 工事担当 | 経理担当 |
|---|---|---|---|
| 案件・工程・日報・安全・図面写真台帳 | 閲覧・編集 | 閲覧・編集 | 閲覧のみ |
| 案件契約額 | 閲覧・編集 | 非表示・編集不可 | 閲覧のみ |
| 協力会社 | 閲覧・編集 | 閲覧・編集 | 閲覧・編集 |
| 見積・予算・発注・原価・請求入金 | 閲覧・編集 | アクセス不可 | 閲覧・編集 |
| CSV出力 | 全て | 閲覧できる項目のみ | 閲覧できる項目 |
| ユーザー管理・操作履歴 | 可 | 不可 | 不可 |

既存ユーザーの権限変更UIは未実装。運用開始時に管理者が役割を決めて作成する。権限変更が必要なら次期改修で専用画面を追加する。

## 計算と整合性
- 暫定粗利＝契約額－計上原価。未発注額や将来原価を含む完成時利益ではない。
- 請求未収＝請求額合計－入金額合計。未請求額・税・出来高は未計算。
- DBの外部キーで存在しない案件・協力会社を拒否。金額の負数、逆転日付、100%超の進捗、過入金をフォームで拒否。
- 編集バージョンを比較して競合をHTTP 409で拒否。登録・編集・監査記録は同一トランザクション。
- 利用者数の変更はPostgreSQLの共通行ロックで直列化。SQLiteはローカル試用専用で、同時書込みの本番運用には使用しない。
- 管理者による直接DB操作・Djangoシェルは上限を迂回し得るため運用担当者に限定。
